# ESPMO Tier Unification — Spec (proposed v01.3)

Status: **APPROVED for implementation** (logic). Export-column naming deferred until
bands are implemented and verified.

## Problem

The tool currently carries **three incompatible definitions of "Tier 1 / Mini,"** plus a
redundant `artTier`:

1. **Band** (drives the document set, via the map): the both-low corner —
   `value < 60 AND avgCx < 2.5`.
2. **govTier config** (`_GT`): `V–C < t1Max` with `t1Max = 60`.
3. **govTier fallback** (hardcoded): `V–C < t1Max` with `t1Max = 50`.

Separately, **`artTier`** is a complexity-only number (`cxi>=75?3 : cxi>=50?2 : 1`,
+PII bump) that `buildArtifacts()` reads to choose documents — i.e. the document set is
currently keyed to raw complexity, not to the band the user sees on the map.

A sweep of a 35-cell value × complexity grid shows **14 cells (40%) disagree** about a
project's tier depending on which definition is consulted. Representative splits:

| value | cxi | avgCx | V–C | band     | govTier(t1=60) | govTier(t1=50) |
|------:|----:|------:|----:|----------|:--------------:|:--------------:|
| 55    | 20  | 0.8   | 53  | **Mini**     | 1 | **2** |
| 59    | 70  | 2.8   | 52  | **Standard** | 1 | 2 |
| 40    | 70  | 2.8   | 33  | **Standard** | 1 | 1 |
| 65    | 70  | 2.8   | 58  | Standard | **1** | 2 |

The corner definition is the only one that sees complexity, so it correctly pushes a
low-value but high-complexity project out of Mini — the V–C cuts cannot.

## Approved single ladder (one definition each, used everywhere)

- **Tier 1 (Mini)** = `value < 60 AND avgCx < 2.5` (the corner) → 5 docs:
  Mini Charter, Mini PMP, baseline set.
- **Tier 2 (Standard)** = everything not Tier 1, 3, or 4 → 6 docs (Standard set).
- **Tier 3 (Full)** = `V–C ≥ 80 OR EDD Next` → Full set (PMP expands).
- **Tier 4 (PAL)** = PAL designation → **forces Full docs + PAL gate package**,
  overriding the natural band.

### Document vs oversight
There is **one ladder**. The document set and the oversight level read the same tier,
with two override rules layered on top of the natural (Tier 1/2/3) band:
- **EDD Next** → routes to Tier 3 (Full). No special document beyond the Tier 3 set.
- **PAL** → Tier 4; forces Full docs **and** adds the PAL gate package, regardless of
  the project's natural band (e.g. a value-60 PAL project = Mini by nature, but gets
  Full + PAL package).

## Implementation checklist

1. **Delete `artTier`** (the `cxi>=75?3 : cxi>=50?2 : 1` formula + PII bump) in BOTH
   computation blocks (~L898 and ~L1503 of Project-Profiler.html).
2. **Define one tier** from: corner (T1), V–C≥80 OR EDD Next (T3), PAL (T4), else T2.
3. **Re-key `buildArtifacts`** to read this tier, not `artTier`.
4. **Collapse the `t1Max` split** (remove the 60 vs 50 disagreement); the corner replaces
   the V–C `t1Max` cut for Tier 1.
5. **Relabel the map** regions: Tier 1 (Mini) / Tier 2 (Standard) / Tier 3 (Full); PAL as
   a Tier-4 badge overlay (PAL is a flag, not a V–C region).
6. **Targeted → Full** rename across map labels, `*_INFO` objects, and the Excel formula
   (~L1774), and the `{TGT/STD/MEA}` map (~L1859).
7. **Tidy** `q-mea` CSS class → `q-min` (cosmetic).
8. **Export/JSON columns** ("Artifact Tier", `artifact_tier`): naming **DEFERRED** —
   decide after bands verified. Likely relabel to a single Governance Tier column.
9. **Verify**: re-run the grid sweep against the implemented logic; confirm the document
   matrix fires 5 / 6 / Full / Full+PAL with no remaining cell where map-tier,
   doc-tier, and oversight-tier disagree (except the intended PAL doc-override).

## Verification gate
Implementation is not "done" until a value × complexity × {EDD Next, PAL, PII} sweep shows
the binder, the map label, and the oversight tier are consistent for every cell, with the
only intended divergence being PAL forcing Full docs above its natural band.
